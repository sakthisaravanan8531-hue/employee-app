# Live serverless acceptance runbook

The owner approved replacing the EC2/ASG/ALB/RDS assignment with a lower-cost serverless app. EC2 stop tests, public database-port probes and RDS failover do not apply. Run active drills in an approved demo/nonproduction environment after deployment. Record resource IDs, Git SHA, timestamps and results without secrets/cookies.

1. **Baseline:** open Amplify AppUrl, sign in, add/edit/list/delete an employee, reload and verify persistence. Run `deployment/scripts/smoke.py` with credentials supplied securely through process environment variables. Confirm the health endpoint's version matches the release commit.
2. **DynamoDB behavior:** create the same normalized email twice; the second request must be HTTP 409. Change an employee email, then create another employee using the old email; it should succeed. Concurrent updates must preserve email uniqueness and may return retryable 409. Clean up test records.
3. **Release and rollback:** push a harmless UI/API change to main, verify Actions deploy succeeds and the new SHA is visible. In a nonproduction copy, deploy a deliberately unhealthy version and verify the live alias returns to its previous version and the job fails. Confirm CRUD after rollback. For a frontend bug, revert/redeploy a known-good main commit. Do not make destructive data-format changes in this drill.
4. **Throttling:** using modest authorized traffic against the demo, exceed the configured two requests/second or five-request burst and observe 429 responses. Stop immediately afterward and confirm ordinary requests recover. Do not load-test broadly or assume throttles provide a billing cap.
5. **Alarms:** temporarily configure a random FAULT_TEST_TOKEN on a demo Lambda through a reviewed operator change. Use an authenticated session and x-fault-token to trigger more than five controlled 500 responses within five minutes, respecting throttling. Confirm BackendErrors enters ALARM and the confirmed SNS email arrives. Remove the token, return to a known-good configuration and confirm the endpoint returns 404 and normal health recovers. A manually forced alarm is not a substitute for real HTTP-500 telemetry.
6. **Access control:** verify unauthenticated employee endpoints return 401 and direct table/secret API calls by an unprivileged test identity are denied. Do not add public access or broad permissions to perform this test.
7. **Cost setup:** inspect the account-wide monthly budget, confirm the intended email and threshold, and check the Billing dashboard for unrelated existing spend. AWS budget updates can be delayed; do not intentionally generate charges merely to test email thresholds.

All live AWS checks remain **not run** until an authorized account identity is connected and the stack is deployed. The local validation report separates SQLite/API tests, mocked DynamoDB command tests and built-Lambda transport tests from cloud acceptance.
